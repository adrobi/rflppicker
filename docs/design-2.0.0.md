# RFLP Picker 2.0.0 — требования и критерии приёмки

Следующий публичный выпуск после 1.6.0 объединяет три этапа [дорожной карты](../ROADMAP.md).
Программа выпускается для Windows и Linux. Сборка под macOS и tetra-primer ARMS-PCR отложены.
Ниже приведены требования к реализации и будущим проверкам.

## Автоматический подбор

Для биаллельного SNP поиск начинается с природного сайта и одного фермента. Следующая ступень —
двойная рестрикция по природным сайтам, затем dCAPS, затем две отдельные аллель-специфичные ПЦР.
Явная настройка «подбирать dCAPS для каждого SNP» сохраняет своё действие.

Поиск останавливается на первой ступени, которая после всех включённых проверок дала хотя бы одну
схему класса `robust`. Найденные ранее схемы `nominal_only` остаются среди кандидатов с указанием
класса. Если надёжных схем нет, пользователь видит доступные `nominal_only`. При приёмке проверить
переход от одного фермента с оценкой `nominal_only` к двум ферментам с оценкой `robust` и выдачу
результата при исчерпании всех ступеней.

## Согласованные требования

1. **Лабораторный список.** В GUI ферменты можно отметить вручную. В GUI и CLI список можно
   загрузить из файла. Неизвестные названия показываются до расчёта. Фильтр поставщиков остаётся
   доступен. Режим «только из списка» допускает любой явно указанный известный фермент, в том
   числе без поставщика. Для двойной рестрикции оба фермента должны входить в список.
   В режиме «предпочитать» сначала учитывается класс качества, затем наличие всех необходимых
   ферментов, затем действующий порядок ранжирования. Проверить выбор представителя среди
   изошизомеров и выдачу с лимитом в одну схему на локус.

2. **Справочник свойств.** В карточке и лабораторном PDF показывать температуру инкубации, буфер,
   чувствительность к метилированию CpG, Dam и Dcm и сведения о star-активности. У каждого значения
   указывать источник и, где существенно, препарат поставщика. Частичное покрытие допустимо.
   Для пропусков выводить «нет данных». Предупреждение при перекрытии сайта с CpG учитывает материал
   рестрикции (геномная ДНК или ПЦР-продукт). Свойства служат справочной информацией.
   Источники и условия распространения справочника предстоит проверить. В генераторе Biopython 1.88
   температуры задаются константами, а признак метилирования характеризует возможность метилирования
   сайта. Для лабораторного листа нужны подтверждённые данные о конкретном ферменте.
   [Генератор словаря Biopython](https://raw.githubusercontent.com/biopython/biopython/biopython-188/Scripts/Restriction/ranacompiler.py)

3. **Двойная рестрикция.** Показывать оба фермента и ожидаемые полосы каждого генотипа.
   При отсутствии подтверждённых общих условий показывать вычислительно подходящую пару
   с пометкой «совместимость условий не подтверждена». Класс `robust` характеризует различимость
   полос. Проверить пример, где каждый фермент по отдельности оставляет неразличимые генотипы,
   а совместная рестрикция позволяет их различить, и пример, где пара также не даёт различения.

4. **Типы вариантов.** Для инделей с известными последовательностями сначала оценивать различия
   длин продуктов без рестрикции. Действует общее правило остановки по `robust`. Далее допустимы
   схемы с одним или двумя ферментами. Для многоаллельных локусов применять те же методы, где
   они применимы. Схема для целого локуса должна различать каждую пару его диплоидных генотипов.
   Для трёх аллелей проверяются шесть генотипов и 15 сравнений. Проверить вставку, делецию,
   недостаточную разницу длин и случай, когда ALT различимы с REF по отдельности, но два генотипа
   локуса дают одинаковые полосы. Область применения dCAPS и запасной ПЦР в этом выпуске —
   биаллельные SNP.

5. **Запасная ПЦР.** Предусмотреть две отдельные реакции для REF и ALT с контролем амплификации
   в каждой. В листе подписать реакции и показать совместную интерпретацию для трёх генотипов.
   Если хотя бы один контроль не прошёл, вывод — «генотип не определён». Проверить эти четыре
   случая и сопоставить ожидаемые результаты с опубликованным примером метода.

6. **Ввод из VCF.** Учитывать фильтр региона. Без выбора образцов брать все явно заданные ALT,
   в том числе в файле без образцов. При выборе образцов оставлять ALT, встретившиеся хотя бы
   в одном известном генотипе выбранных образцов. Пропущенный генотип не подтверждает REF.
   Аллели одной записи образуют один локус. Для символической записи с неизвестной последовательностью
   указывать причину пропуска. Проверить несколько ALT, пропуски генотипов, расхождение REF с FASTA
   и одновременное использование отдельного фонового VCF.

7. **Ввод по rsID.** Поддержать онлайн-поиск и поиск по полю ID локального VCF для нужной сборки.
   Показывать вид, сборку, контиг, координату, REF и ALT. Принимать однозначное соответствие виду
   и сборке после сверки REF с FASTA. Неоднозначное соответствие получает отдельный статус.
   Покрытие внешнего источника проверить на контрольных примерах овцы и риса.

8. **Файл проекта.** Сохранять параметры, идентификатор сборки, версии модели и справочника,
   результаты и ручной выбор схем. Проверить перенос на другой компьютер с недоступным исходным FASTA:
   результаты и гели должны открываться, а лабораторный лист — воспроизводиться с тем же выбором.
   Для нового расчёта пользователь указывает расположение необходимых исходных файлов.

9. **Индексированные данные.** Читать готовый BGZF FASTA с индексом при нормализации, подборе и
   полногеномной проверке специфичности без создания распакованной копии. Сопоставить результаты
   с обычным FASTA. Фоновый VCF с индексом tabix читать по нужным областям, обычный VCF —
   последовательно. Проверить совпадение результатов, в том числе на границах и при перекрытии
   окон. На большом файле зафиксировать запрошенные области и время обоих способов чтения.

10. **Модель геля.** Новая версия оценки учитывает концентрацию агарозы по явно описанной модели
    разрешения. Выбранный маркер длин отображается на геле. В сценариях просмотра учитывать
    неполную рестрикцию и ожидаемую яркость полос гетерозиготы. Одной разницы яркости недостаточно
    для присвоения класса `robust`. Проверить состав и размеры полос, затем влияние настроек
    на различимость. Сохранять версию модели и параметры в проекте и экспорте. Модель 1.6.0
    остаётся доступной для воспроизведения прежних оценок.

11. **Приёмка и независимое ревью.** На прежних сценариях при модели 1.6.0 и отключённых новых
    режимах сравнить значения прежних столбцов и порядок строк Results с тегом v1.6.0.
    Для каждого намеренного изменения результата описать условия в CHANGELOG. Для каждого нового
    метода проверить как минимум различимый случай и случай отклонения схемы. Раздельно описать
    результаты на опубликованных примерах и искусственных данных. Пять восстановленных локусов
    овцы и риса служат контролем прежних сценариев. Прежние 17 анализов полностью не восстановлены,
    экспериментальная специфичность ПЦР в 1.6.0 не проверялась.
    Проверить русский и английский интерфейсы, CLI, экспорт и запуск готовых сборок Windows и Linux.
    До публикации обязательно независимое ревью через делегирование. Исполнителя, объём ревью,
    материалы и порядок проверки замечаний согласовать с пользователем ближе к выпуску, до передачи
    работы. Геномы, публикации и результаты из reg/release160 хранятся вне Git-репозитория.
    [Описание проверки 1.6.0](assay_design.md#проверка-выпуска-160)
